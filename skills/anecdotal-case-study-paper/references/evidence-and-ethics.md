# Evidence and ethics

## Evidence ledger

Create one row per event. Do not merge unlike events into a single impressive number.

| Field | What to record |
|---|---|
| Event ID | Date, place, participants, event type |
| Exact claim | Original wording, speaker, and language |
| Reported duration | Number, unit, and reference frame |
| External duration | Start, endpoint, and time source |
| Evidence source | Direct observation, chat log, audio, third party, memory |
| Evidence grade | A, B+, B, or C |
| Confounders | Queue, switching, network, sleep, task difficulty |
| Supported claim | The narrowest claim the evidence supports |
| Unsupported claim | The stronger claim the evidence cannot support |

## Grading

- `A`: instrumented or independently verifiable.
- `B+`: repeated direct observation with a usable record.
- `B`: single direct observation with a usable record.
- `C`: ambiguous, second-hand, memory-only, or unmeasured.

Use grades to limit inference, not to decorate the paper. A `C` observation can be interesting and still cannot support a precise ratio.

## Handling ambiguity

When wording is ambiguous:

- name the speaker;
- name the reference frame;
- state possible interpretations;
- exclude the case from quantitative synthesis if the unit cannot be resolved;
- preserve the ambiguity in the limitations section.

When a source is a voice transcript:

- correct names only when the context is clear;
- note the correction;
- do not treat transcript punctuation as a verbatim quotation unless checked;
- prefer a text reconstruction or a short quote over a screenshot.

## Assumptions and calculations

Every ratio needs a stated assumption. For example:

- `gamma = external duration / promised duration`;
- `compression = reference preparation period / reported preparation period`.

If the source says "a few seconds," calculate a range rather than inventing one exact value. State that the range is illustrative.

## Privacy and consent

- Use a real name only when the user has a legitimate reason and explicit permission.
- Default to a pseudonym, initials, or "the participant" for public artifacts.
- Avoid a private chat screenshot unless the user explicitly asks for it and the participants consent.
- Do not expose addresses, phone numbers, student IDs, employer data, or unrelated personal details.
- Treat school and workplace names as potentially identifying.
- Put a clear note in the draft that public release requires consent.

## Defamation and factual boundaries

Do not state or imply:

- a real person has a medical condition;
- a real person has a superpower as fact;
- a real person cheated, lied, or committed misconduct without evidence;
- a named athlete or institution endorses the paper.

Use phrases such as "the observer described," "the participant reported," "the evidence is compatible with," and "the hypothesis remains untested."

## Citations

- Use real sources for real claims.
- Verify author, year, title, venue, and pages when precision matters.
- Use cultural or fictional references as clearly marked cultural references, not empirical support.
- Never fabricate a citation to make the paper look more academic.
- If a source cannot be verified, mark it as an informal reference or remove it.

## Serious humor

The safest and strongest technique is:

- neutral methods language;
- transparent evidence limitations;
- one absurd but explicitly labeled hypothesis;
- a conceptual figure that visualizes the metaphor;
- a conclusion that refuses to overclaim.

The joke should survive because the reader can see exactly where the evidence stops.
